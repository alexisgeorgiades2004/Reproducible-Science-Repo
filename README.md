# Reproducible-Science-Repo
BIOINFO-M291 Class Repository

# Project Title

> One or two sentences on the scientific question this project addresses.

This repository is organized so that every result can be traced back to the data, code, configuration and environment that produced it. Rules live in `CLAUDE.md`, inputs live in `data/`, and all outputs are written to `results/`, `figures/` and `reports/`.

## Project structure

```
project/
├── README.md
├── CLAUDE.md
├── data/
│   ├── raw/
│   ├── metadata/
│   └── processed/
├── src/
├── workflows/
├── configs/
├── results/
├── figures/
├── reports/
├── tests/
└── environment/
```

| Folder / file | Purpose | Direction |
|---|---|---|
| `README.md` | What the project is and how to reproduce it (this file) | Read by people |
| `CLAUDE.md` | Rules the AI agent must follow in this project | **Input** (rules) |
| `data/raw/` | Original data exactly as obtained. Never edited | **Input** (data) |
| `data/metadata/` | Data dictionaries, sample sheets, sources, licenses, download dates | **Input** (data) |
| `data/processed/` | Cleaned or transformed data generated by code | Output |
| `src/` | Reusable code: functions, modules, scripts | Code |
| `workflows/` | Ordered pipelines that chain the steps together | Code |
| `configs/` | Parameters, seeds, paths and thresholds (no magic numbers in code) | **Input** (settings) |
| `results/` | Tables, model outputs, statistics from each run | Output |
| `figures/` | Plots and images | Output |
| `reports/` | Written summaries and notebooks that interpret the results | Output |
| `tests/` | Checks that code and data behave as expected | Code |
| `environment/` | Pinned package versions and environment files | **Input** (setup) |

## Set up the structure

Git does not track empty folders, so the commands below also add a `.gitkeep` placeholder to each one. Run them from the root of your cloned repo.

**Windows (PowerShell)**

```powershell
$dirs = "data/raw","data/metadata","data/processed","src","workflows","configs","results","figures","reports","tests","environment"
foreach ($d in $dirs) {
    New-Item -ItemType Directory -Force -Path $d | Out-Null
    New-Item -ItemType File -Force -Path "$d/.gitkeep" | Out-Null
}
if (-not (Test-Path CLAUDE.md)) { New-Item -ItemType File -Path CLAUDE.md | Out-Null }
```

**Mac / Linux (bash)**

```bash
mkdir -p data/{raw,metadata,processed} src workflows configs results figures reports tests environment
for d in data/raw data/metadata data/processed src workflows configs results figures reports tests environment; do
  touch "$d/.gitkeep"
done
touch CLAUDE.md
```

Then commit the result:

```bash
git add .
git commit -m "Create reproducible project structure"
git push
```

## Rules for working in this project

These are summarized here for people. The authoritative version for the AI agent is `CLAUDE.md`.

1. **Raw data is read-only.** Never modify, rename or overwrite anything in `data/raw/`. Cleaned versions go in `data/processed/`.
2. **Document every dataset.** Each file in `data/raw/` gets an entry in `data/metadata/` (source, date obtained, license, description).
3. **Code produces outputs, not hand edits.** Every file in `data/processed/`, `results/` and `figures/` must be regenerable by running code in `src/` or `workflows/`.
4. **Parameters live in `configs/`.** Seeds, thresholds and paths are set there, not hard-coded.
5. **Set and record random seeds.** Every stochastic step uses a seed from `configs/`, and the seed is recorded with the output.
6. **Pin the environment.** After each run, save package and language versions to `environment/`.
7. **Name outputs by run.** Save outputs in a subfolder or filename tied to the experiment or run (for example `results/exp01-baseline/`).
8. **Test before trusting.** Add or run checks in `tests/` when code or data changes.
9. **Explain in `reports/`.** Each report states the question, the method, the data version, the parameters used and the conclusion.
10. **Commit per experiment.** One clear commit per experiment, with a message describing what changed and why.

## Reproducing a result

1. Clone the repository and open a terminal in its root.
2. Recreate the environment from the files in `environment/`.
3. Place the raw data in `data/raw/` as described in `data/metadata/`.
4. Run the workflow in `workflows/` with the settings in `configs/`.
5. Compare the new files in `results/`, `figures/` and `reports/` with the committed versions.

## Using this repo with Claude Science

1. Clone this repo to a local folder (outside OneDrive is safest) and grant that folder to your Claude Science project with **Read & write** access.
2. In the project's custom instructions, tell Claude to read `CLAUDE.md` and this README at the start of every session, and to save all outputs into the folders above.
3. Ask for each experiment by name and folder, for example: "Run exp02 following CLAUDE.md. Write code to `src/`, outputs to `results/exp02/`, figures to `figures/exp02/` and a summary to `reports/`."
4. Claude Science also keeps its own versioned artifacts with a provenance record. Ask Claude to copy or export final outputs into this repo's folders so that git remains the single source of truth.
5. Ask Claude to end each experiment by listing which rules it applied, the seed, the environment versions, and the git commit it started from.

## Versioning

Record the commit hash (`git rev-parse HEAD`) in every report so each result can be tied to the exact state of the code, configuration and rules that produced it.
