# Reproducible Science Environment

A Git-versioned working setup for reproducible computational science, built to run inside **Claude Science**. It is used to redo the **scRNA-seq Immunotherapy Tumor Response Analysis** example, and it is meant to be reused for future projects.

The goal is that every result can be traced back to the exact data, code, parameters, environment and rules that produced it, including the many small decisions an AI agent makes along the way.

## What has to be recorded

| Requirement | Where it lives |
|---|---|
| Traceable inputs | `data/raw/`, `data/metadata/` |
| Explicit decisions | `reports/` and commit messages |
| Executable code | `src/`, `workflows/` |
| Configuration and parameters | `configs/` |
| Recorded environment | `environment/` |
| Verified outputs | `results/`, `figures/`, `tests/` |

## Project structure

```
project/
├── README.md
├── CLAUDE.md
├── data/
│   ├── raw/
│   ├── metadata/
│   └── processed/
├── src/
├── workflows/
├── configs/
├── results/
├── figures/
├── reports/
├── tests/
└── environment/
```

| Folder / file | Purpose | Role |
|---|---|---|
| `README.md` | What this project is and how to reproduce it (this file) | Documentation |
| `CLAUDE.md` | Rules the AI agent must follow in this project | **Input** (rules) |
| `data/raw/` | Original data exactly as obtained. Made read-only after download | **Input** (data) |
| `data/metadata/` | Data sources, download dates, licenses, sample sheets, data dictionaries | **Input** (data) |
| `data/processed/` | Cleaned and intermediate data generated by code | Output |
| `src/` | Reusable code: functions, modules and scripts | Code |
| `workflows/` | Ordered pipelines from raw data to final figures | Code |
| `configs/` | Parameters, random seeds, thresholds and paths | **Input** (settings) |
| `results/` | Tables, statistics and model outputs from each run | Output |
| `figures/` | Plots and images | Output |
| `reports/` | Written summaries that interpret the results | Output |
| `tests/` | Checks that code and data behave as expected | Verification |
| `environment/` | Package versions and environment files | **Input** (setup) |

The structure does not have to be followed exactly, but any change should be recorded here and in `CLAUDE.md`.

## How data flows

```
data/raw  ->  data/processed  ->  analysis  ->  results/  ->  figures/  ->  reports/
 (fixed)     (regenerable)                      (regenerable)
```

- Raw data is collected or downloaded once, then locked as read-only.
- Everything downstream can be fully regenerated by running the workflows.
- Each arrow is a piece of code, and the workflows document what actually happened.

## Set up the structure

Run these commands from the root of the cloned repository. Git does not track empty folders, so a `.gitkeep` placeholder is added to each one. Existing files are not overwritten.

**Windows (PowerShell)**

```powershell
$dirs = "data/raw","data/metadata","data/processed","src","workflows","configs","results","figures","reports","tests","environment"
foreach ($d in $dirs) {
    New-Item -ItemType Directory -Force -Path $d | Out-Null
    if (-not (Test-Path "$d/.gitkeep")) { New-Item -ItemType File -Path "$d/.gitkeep" | Out-Null }
}
if (-not (Test-Path CLAUDE.md)) { New-Item -ItemType File -Path CLAUDE.md | Out-Null }
```

**Mac / Linux (bash)**

```bash
mkdir -p data/{raw,metadata,processed} src workflows configs results figures reports tests environment
for d in data/raw data/metadata data/processed src workflows configs results figures reports tests environment; do
  touch "$d/.gitkeep"
done
touch CLAUDE.md
```

Then commit and push:

```bash
git add .
git commit -m "Create reproducible project structure"
git push
```

## Rules

These are summarized here for people. `CLAUDE.md` is the version the AI agent follows.

1. **Raw data is read-only.** Never modify, rename or overwrite anything in `data/raw/`.
2. **Document every dataset.** Each raw file has an entry in `data/metadata/` (source, date obtained, license, description).
3. **Code produces outputs.** Every file in `data/processed/`, `results/` and `figures/` must be regenerable by running code in `src/` or `workflows/`. No hand edits.
4. **Parameters live in `configs/`.** Seeds, thresholds and paths are set there, not hard-coded.
5. **Record random seeds.** Every stochastic step uses a seed from `configs/`, and the seed is recorded with the output.
6. **Pin and record the environment.** Save full package and language versions to `environment/` after each run.
7. **Keep environments small.** Use several small environments matched to analysis steps rather than one environment with everything.
8. **Name outputs by run.** Outputs go in a subfolder tied to the analysis or run, for example `results/scrna-immunotherapy/`.
9. **Test before trusting.** Add or run checks in `tests/` when code or data changes, and verify outputs before reporting them.
10. **Explain in `reports/`.** Each report states the question, method, data version, parameters and conclusion, and separates measured results from interpretation.
11. **Commit at every step.** Small commits with clear messages, pushed regularly.

## Reproducing a result

1. Clone the repository and open a terminal in its root.
2. Recreate the environment from the files in `environment/`.
3. Place the raw data in `data/raw/` as described in `data/metadata/`.
4. Run the workflow in `workflows/` using the settings in `configs/`.
5. Compare the new files in `results/`, `figures/` and `reports/` with the committed versions.

## Using this repository with Claude Science

Claude Science does not natively read `CLAUDE.md` or `AGENTS.md` files, and it has no built-in rules feature. Its configuration is mostly web-based, so the rules are enforced in layers:

1. **Folder access.** Clone the repository to a local folder outside cloud-synced locations such as OneDrive, then grant that folder to the Claude Science project with **Read & write** access.
2. **Project settings.** In the project's custom instructions, tell Claude to read `README.md` and `CLAUDE.md` from the granted repository folder at the start of every session and to follow them. A working example:

   ```
   The repository folder granted to this project is the source of truth.
   At the start of every session, read README.md and CLAUDE.md in that folder and follow them.
   Save all code, data, results, figures and reports in the folders described there.
   ```

3. **Skills.** Convert key repeatable steps (such as setting up a project or documenting an analysis) into skills, and tell Claude in the project settings to use them.
4. **Exports.** Claude Science keeps its own versioned artifacts with provenance. Final outputs are copied into this repository's folders so that Git remains the single source of truth.
5. **End-of-task report.** Each analysis ends with Claude listing the rules it applied, the seeds used, the environment versions, and the Git commit the work started from.

## Analysis: scRNA-seq Immunotherapy Tumor Response

This repository reproduces the Claude Science example analysis "scRNA-seq Immunotherapy Tumor Response Analysis" in its own environment. The work follows the flow above:

1. Obtain the input data into `data/raw/` and document it in `data/metadata/`.
2. Write the processing and analysis steps as code in `src/` and `workflows/`, with parameters in `configs/`.
3. Record the environments and seeds in `environment/` and `configs/`.
4. Write tables to `results/`, plots to `figures/` and the written summary to `reports/`.
5. Verify that the results match the original example and that a fresh run reproduces them.

## Versioning

- Commit after each meaningful step: structure, environment, each workflow stage, results and report.
- Record the commit hash (`git rev-parse HEAD`) in every report so each result is tied to the exact state of the code, configuration and rules that produced it.
- Tag milestones, for example `git tag v1.0`, and push tags with `git push --tags`.
